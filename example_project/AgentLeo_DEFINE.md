# Agent Leo · DEFINE 拆解(F 功能设计的范本:persona + 多 agent)

> **看颗粒度,别照抄。** Agent Leo 是北师大心理学部的 AI 平台(已上线 deepsy.ai),把 **112 位心理学大师**(100 位历史上著名心理学家 + 12 位北师大在职教授)做成了 AI 数字分身。你现在就能去和"弗洛伊德"聊两句。
> 它最值得学的是 DEFINE 的 **F(功能设计)**——怎么用一个文件承载一个"专家人设",以及多个 agent 一起说话时怎么编排。下面用 D/E/F 视角组织,重点在 F。

---

## D · 域分析(简)
- **专家行为**:选导师、了解一个学派,过去靠读静态主页/论文,门槛高、又隔着距离。
- **缺失环节**:你没法"先和这位老师/这个学派聊两句再决定"。
- **Leo 补什么**:让每位大师/导师有一个**可对话的数字分身**——**从"个人主页时代"进入"个人智能体时代"**:过去看导师是看他的主页(静态),未来选导师前,先和他的 agent 聊一聊(动态)。

## E · 体验(简)
- **用户**:想选导师的学生 / 想快速理解某学派的人。
- **刚性**:准确传达这位大师的理论与风格;**情感**:像真的在和"他"对话;**成长**:在对话里把一个学派学明白。
- **匿名优先**:降低"和大师对话"的心理门槛。

---

## F · 功能设计(重点)

### 1. 一个 persona = 一个 SKILL.md 文件
每位大师就是**一个 420 多行的 SKILL.md 人设文件**(nuwa-skill 格式),里面写清这位大师的:**生平、理论、语气、边界**。数据库里只存元数据,人设本身存在文件系统里。

> **换一个文件,就换一位大师。** 这正是"换技能 = 换专家"在真实产品里的样子——你不需要为每位大师写新代码,只需要写一个新的人设文件。

**给你的启示**:如果你的项目要做"多个角色"(不同流派的咨询师、不同学科的导师),别用一堆 if-else,用**一个角色一个人设文件**。加角色 = 加文件。

### 2. persona 文件该写什么(人设三段式的放大版)
- **身份 / 生平**:他是谁、活在什么年代、做过什么
- **理论内核**:他的核心观点、术语、思考方式(这是"专业内核",要准)
- **语气**:他会怎么说话(弗洛伊德和罗杰斯语气完全不同)
- **边界**:他**是一个合成的数字分身,不是真人,不做诊断/治疗**

### 3. 多 agent 编排:两种模式(这是设计问题,不是玄学)
Leo 最有意思的功能是**群聊**——拉几位大师一起讨论一个问题。多个 agent 怎么"编排",有两种模式,对话质量完全不同:

| 模式 | 怎么发言 | 效果 | 什么时候用 |
|---|---|---|---|
| **圆桌 Roundtable** | 顺序发言,**后发言者看得到前面说了什么** | 会互相回应、甚至辩论(弗洛伊德 vs 荣格吵"潜意识") | 你想要"思想碰撞" |
| **自由 Freeform** | 所有 agent **并行**作答,互不影响 | 速度快,各说各的独立观点 | 你想听不同流派各自的独立看法 |

> **关键设计决策**:"谁先说、能不能看到别人说的"——这些安排,直接决定了对话质量。如果你的项目要用多个 agent,**先想清楚要圆桌还是自由**。

### 4. 实现要点(I,指向模块 0/1)
后端用 `claude -p` CLI 驱动;每个 persona 就是一个 skill 文件——**实现本身你在 `0_agent_basic/s5`(换技能=换专家)和 `1_claude_code_basic/c3`(子 agent)里已经学过。**

---

## 这个项目教你的三件事
1. **一个"专家人设" = 一个文件**:换文件就换专家,加角色就加文件,不写死在代码里。
2. **persona 要写全四件**:身份/理论内核/语气/边界——尤其边界(它是合成分身,不是真人)。
3. **多 agent 编排是设计题**:圆桌还是自由,取决于你要"碰撞"还是"并列",不是随便接起来就行。
