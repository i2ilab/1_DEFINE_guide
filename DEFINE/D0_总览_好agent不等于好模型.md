# D0 · 总览 —— 好 agent ≠ 好模型

> **目标**:在动手之前,先装上一副「设计者的眼睛」——看懂 DEFINE 六步、双钻石、人本七原则,知道自己接下来五步在干什么。
> **前置输入**:上过模块 0/1(能造一个能跑的 agent),或至少知道 `Agent = LLM + Harness`。
> **产出物**:—(这是导览,读完即可进入 D1)。
> **配套 skill**:—

## 先打个气:你不是来学写代码的

很多同学一听「做 AI 产品」就慌:我不会前端、不会架构、不会调模型。**放松——那些是工程师的活,而且你已经在模块 0/1 学过「怎么造」了。**

今天开始的两支柱,教的是工程师**不教、也常做不好**的两件事:

- **DEFINE(定义)**:动手写 prompt 之前,先想清楚「为谁造、造什么、边界在哪、对话怎么流动」。这是**设计**。
- **Eval(评估)**:做出来之后,凭什么说它「有用、安全、稳定」?这是**科学**。

这两件事,恰好是你的**三重优势**:**懂人**(访谈、共情、洞察是你的基本功)、**懂测量**(信度效度、量表是你的训练)、**懂边界**(「不伤害」的伦理意识你最敏感)。**「为人而设计、用证据说话」——你比工程师在行。**

## 新想法:好 agent ≠ 好模型

很多人以为做 AI 产品就是「选个更强的模型」。错。Don Norman(《设计心理学》作者)有句话:**好产品 = 好的「人机体验」,模型只是其中一环。**

一个用最强模型驱动的心理陪伴 agent,如果开场白冷冰冰、不会在该停下时倾听、遇到危机不知道转介——它再「聪明」也没人敢用,甚至有害。所以本模块**不教你调模型**(那是工程师的活),而是教你**设计体验、评估安全**:这个 agent 为谁服务?该有什么性格?对话怎么流动?哪里必须让人把关?怎么证明它可信?

## 新想法:DEFINE 六步 —— 阅读顺序就是设计顺序

DEFINE 是把「设计思维 + 人本 AI 原则」落到 agent 上的一套操作卡片,六个字母对应六步:

| 字母 | 阶段 | 一句话 | 本模块 |
|---|---|---|---|
| **D** | Domain 域分析 | 这专业在解决什么?哪个环节该让 AI 补位? | D1 |
| **E** | Experience 体验 | 用户是谁?一轮对话怎么走? | D2 · D3 |
| **F** | Feature 功能 | 要哪些系统提示、技能、工具、记忆、边界? | D4 · D5 |
| **I** | Implementation 实现 | 用 Harness 搭起来 | ← 模块 0/1 |
| **N** | Navigation 测试 | 常见/边界/危险场景下表现如何? | **Eval 支柱** |
| **E** | Evolution 演化 | 靠日志发现问题,小步迭代,回到 D | **Eval 支柱** |

**关键提醒:阅读顺序 = 设计顺序。先想清楚「领域和人」(D·E),再决定「造什么」(F),最后才谈怎么测、怎么迭代(N·E)。** 最常见的错误,就是**一上来就写 prompt**——写 prompt 是 F 阶段的事,前两步没做,prompt 写得再花也是空中楼阁。

> 本模块 = DEFINE 的 **D·E·F(定义)** + **N·E(评估演化)**。中间的 **I(实现/造)** 你在 `0_agent_basic/s5` 和 `1_claude_code_basic/c1–c4` 已经学过,这里不重复。

## 新想法:双钻石 —— 先发散,再收敛

设计界的经典模型「双钻石(Double Diamond)」:两次「先张开、再收拢」。DEFINE 正好套在上面。

- **第一颗钻 = 找对问题**:D 阶段大量发散调研 → E 阶段收敛到「要解决的那一个问题」。很多项目失败不是方案不好,而是**一开始就在解决一个错误的问题**。
- **第二颗钻 = 做对方案**:F 阶段发散地想各种功能 → I 阶段收敛到一个能跑的 MVP。

新手最容易犯的是「**单钻石**」——听到一个需求就冲去写代码。双钻石提醒你:**每一步都要先张开、再收拢。**

## 新想法:人本 AI 七原则(贯穿每一步)

这七条出自 Google PAIR、微软 HAX、Stanford HAI 三套权威指南,是你在 D1–D5 每一步都要回头对照的准则:

1. **人在环(HITL)**——关键/高风险决策必须由人把关,AI 不独自定夺。
2. **透明可解释**——让用户知道「我在跟 AI 说话」,并能解释「它为什么这么建议」。
3. **心智模型对齐**——用户的「期望」= AI 的「实际能力」。**这就是你们学的「知情同意」。**
4. **优雅失败**——不会时承认局限、给出路,不硬编假答案。**这就是「专业边界的诚实」。**
5. **信任校准**——既不过度信任(盲信酿错),也不信任不足(该用不用)。
6. **用户控制**——能暂停、能纠正、能退出。
7. **伦理包容**——公平、隐私、无障碍。

**你的专业训练,和人本 AI 设计高度相通。** 完整自查表见 `checklists/人本AI七原则自查表.md`。

## 痛点对比

| 😌 简单·看不出必要 | 「我先把 prompt 写出来,边写边想」——反正能跑,想那么多干嘛 |
|---|---|
| 🔥 复杂·痛点凸显 | 三天后你发现:agent 能聊,但没人说得清它「帮谁、解决什么、危机怎么办」;答辩第一问「你为谁设计的?」就卡住;想改又不知从何改——因为**从来没定义过**。DEFINE 六步就是那张「先想清楚再动手」的地图 |
