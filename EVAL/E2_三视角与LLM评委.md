# E2 · 三视角与 LLM 评委 —— 结果对,不代表过程对

> **目标**:学会从三个视角看 agent,并会用「LLM 当评委」批量打分——同时躲开它的陷阱。
> **前置输入**:E1 的四维尺子(T6 已开始填)。
> **产出物**:`templates/T6_四维评估报告.md` 续填(三视角 + LLM 评委 rubric)。
> **配套 skill**:`/eval-design`｜**示例**:`example_project/HEAI_EVAL.md`

## 先打个气:别只看「答对没」

期末考只看最终答案的老师,会把「蒙对的」和「真会的」打一样分。评 agent 也一样——**只看结果的评估是脆弱的。** 你要像批改解答过程一样,看它「怎么想的」。

## 新想法:三视角,缺一不可

评一个 agent,从三个视角看:

| 视角 | 看什么 | 为什么 |
|---|---|---|
| **过程 trajectory** | 它中间怎么一步步想、怎么调工具 | 看它的「解题过程」对不对 |
| **工具 tool-use** | 该调工具时调了吗?调对了吗? | 例:该查危机资源库时查了吗 |
| **结果 task** | 最终任务完成得怎么样 | 用户的问题解决了吗 |

**核心洞见:结果对,不代表过程对。** 它可能**蒙对了**,下次同类问题就翻车。一个「碰巧说对话」的 agent,和一个「按正确流程说对话」的 agent,分数不该一样。

## 新想法:LLM-as-Judge —— 让一个 AI 打分

你的 agent 可能产生成百上千条对话,人工一条条评评不过来。解法:**让另一个 LLM 当评委**——给它一份评分标准(rubric),让它逐条打分。

但**评委也会看走眼**,两个著名陷阱:

- **陷阱① 位置/长度偏见**:偏爱更长的答案、偏爱排在第一个的答案。
- **陷阱② 自评偏高**:让一个模型评它自己(或同家族模型),分数会偏高。

**对策**:

1. **rubric 写得很细**——别让评委自由发挥,把「5 分/1 分」写死(接 E1)。
2. **位置随机化**——比较两个答案时,随机谁排前面。
3. **用独立模型**当评委——别自己评自己。
4. **抽样人工复核**——关键场景(尤其**安全**)一定人复核,不全交给 AI 评委。

> **一句话:AI 评委负责规模,人负责校准。** 这也是「AI 拆活、人把关」在评估里的样子。

## 新想法:业界基准与心理专项

业界有标准化「统考卷」(benchmark),可横向比模型:

- **通用 agent**:GAIA(真实任务)、SWE-bench(修真实代码 bug)。
- **对话/工具**:τ²-bench(多轮工具调用)。
- **心理专项**:MindBench(心理对话质量)、Mind-Eval、PsychEval(共情、安全、专业性)——**这些才和你项目直接相关**。

**两条警示**:①基准会被「刷分」(厂商针对性优化);②**通用考卷测不出你这个具体项目的真实安全。** 所以除了看基准,你**必须自己为项目设计评估**(就是 E1–E4 在做的事)。

## 操作步骤

1. **收集轨迹**:让 agent 跑 3–5 个测试场景,把它的**过程 + 工具调用 + 结果**都记下来。
2. **三视角各评一句**:每个场景,分别写过程/工具/结果的观察(填 T6 三视角栏)。
3. **写 LLM 评委 rubric**:把 E1 的四维标准整理成一份能喂给评委的 rubric。
4. **跑 LLM 评委**:用一个**独立模型**给对话逐条打分。
5. **抽样人工复核**:自己复核 20% 的打分,尤其安全相关的,看评委有没有看走眼。
6. **记录偏差**:如果人评和 AI 评差很多,记下来——那是评委不可靠的信号。

## 痛点对比

| 😌 简单·看不出必要 | 「我让 ChatGPT 给我的 agent 打分,它说 9 分,很专业」 |
|---|---|
| 🔥 复杂·痛点凸显 | 问题:①你用同家族模型评自己(自评偏高);②你没给 rubric,它凭感觉;③它偏爱你那段又长又客气的回复(长度偏见)——这个 9 分毫无意义。加上独立评委 + 细 rubric + 人工抽检,分数才可信 |

## 门禁检查(过了才进 E3)

- [ ] 每个测试场景,过程/工具/结果三视角都评了
- [ ] 理解「结果对 ≠ 过程对」,能举一个「蒙对」的例子
- [ ] 写了一份能喂给 LLM 评委的细 rubric
- [ ] 用了**独立模型**当评委,并做了抽样人工复核
- [ ] 知道通用基准测不出你项目的真实安全

## 思考题

> 你的 LLM 评委,在「安全」这一维上打的分,你敢直接信吗?
> ——不敢。因为安全是**一票否决**,不能交给会看走眼的 AI 评委。下一步 E3,我们专门、用人来测危机安全。
